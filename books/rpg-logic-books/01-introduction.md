# RPG.LOGICについて

はじめまして。

本プロジェクトは、**TypeScriptとReactを使って、複雑なRPG戦闘ロジックの設計・実装をやってみる**、という実験的試みです。  
本章ではまず、その「複雑なRPG戦闘ロジック」の仕様の概要を説明しつつ、設計・実装の例を取り上げていきます。

皆さんはテーブルトークRPGを知っていますか。会話とダイス (サイコロ) を使って進めていくという、今のコンピュータRPGのシステムの原型です。  
僕はやったことは無いのですが、昔からテーブルトークRPGのルールブックを読むのは好きでした。  
中でも、GURPS (ガープス) という Steve Jackson 氏によって創作されたこのゲームは、もう流行ったのは30年以上前ですが、かなりハチャメチャで、戦略性に富み、ルールも複雑なものでした。

今回は、このGURPSのルールを僕なりに簡略化し、戦闘ロジックを実装してみたいと思います。

※ GURPS (Generic Universal RolePlaying System) はSteve Jackson氏によって創作され、Steve Jackson Games社から出版されているTRPGです。本プロジェクトはGURPSを題材とした独立した非商用のファンプロジェクトであり、Steve Jackson Games社とは関係ありません。GURPSおよび関連する原著作物の権利は、それぞれの権利者に帰属します。

## プロジェクト概要

### ディレクトリ構成

コードは、主に**ドメイン層**と**UI層**の2層で構成します。  
ドメイン層は純粋なTypeScriptコード(.ts)、UI層にはReactコード(.tsx)で実装していきます。  
この**2層の責務を完全に分離すること**が、本プロジェクトの設計における基本方針です。  
ただし、解説においては、ドメインモデルの設計が主なので、ReactコードによるUI層の解説は一切省略していく予定です。ご容赦ください。

```
src/
├── domains/               … ドメイン層 (.ts)
│   ├── Character/
│   │   ├── index.ts       … class Character
│   │   ├── Parameters.ts  … class Parameters
│   │   └── Equipments.ts  … class Equipments
│   └── Combat/
│       ├── index.ts       … class Combat
│       └── roll.ts        … function getRoll
│
└── parts/                 … UI層 (.tsx)
    ├── index.tsx          … 初期画面
    ├── Docs               … ドキュメント画面
    ├── Setup              … 編成画面
    └── Combat             … 戦闘画面

```

## キャラクタの実装

ゲームはキャラクタ作成から開幕します。  
キャラクタ作成は主に、ポイントを振り分けて、能力値・技能値と呼ばれるパラメータを設定するドメインと、武器・盾・鎧など装備を整えて、戦闘に備えるドメインに分かれます。

### 1. パラメータ

キャラクタ作成は、CP (キャラクタポイント) を各能力値や技能値に振り分けて行います。  
GURPSオリジナルは、100CPを振り分けるのですが、僕の作る簡易版は10CPで行います。

能力値には、**ST(筋力)**、**DX(敏捷力)**、**IN(知力)**、**HT(生命力)** の4つがあります。  
また、本来のテーブルトークRPGは、登攀だとか、鍵開けだとか、色々な場面で判定に使う「技能 (技能値) 」を設定するのですが、本プロジェクトは戦闘ロジック限定なので、技能総数をだいぶ減らしています。

能力値は 10 を基準値、技能値はいずれかの能力値を基準値とし、高く設定するためにはより多くのCPを消費します。消費CPと能力値・技能値の増加は、下記表に対応します。

##### 消費CPと能力値・技能値の対応表

| 能力値・技能値 | 消費CP |
| ------- | ---- |
| 基準値に等しい | 0CP  |
| 基準値+1   | 1CP  |
| 基準値+2   | 2CP  |
| 基準値+3   | 4CP  |
| 基準値+4   | 8CP  |

##### 技能表

| 技能   | 基準 | 説明                      |
| ---- | -- | ----------------------- |
| 武術   | ST | 重装備で近接戦闘を行うための技能。       |
| 怪力   | ST | 加ダメージ量の算出に影響する技能。       |
| 剣術   | DX | 軽装備で近接戦闘を行うための技能。       |
| 運動   | DX | 回避判定の目標値の算出に影響する技能。     |
| 青の魔法 | IN | 回復・防御・補助などを行う魔法を扱える技能。  |
| 赤の魔法 | IN | 炎や雷を操り攻撃・補助を行う魔法を扱える技能。  |
| 緑の魔法 | IN | 風や木を操り攻撃・防御を行う魔法を扱える技能。 |
| 鍛錬   | HT | Hp (耐久値) の算出に影響する技能。   |

パラメータは、下記のようにコードで定義します。

```TypeScript
// src/domains/Character/Parameters.ts

// CP
const POINT_STEP = [0, 1, 2, 4, 8] as const

type Point = typeof POINT_STEP[number]

// パラメータのキー
const PARAMETER_KEYS = [
  '筋力', '敏捷力', '知力', '生命力', // 能力値
  '武術', '怪力', '剣術', '運動', '青の魔法', '赤の魔法', '緑の魔法', '鍛錬' // 技能
] as const

type ParameterKey = typeof PARAMETER_KEYS[number]

// パラメータの定義
const PARAMETERS: Record<ParameterKey, { base: ParameterKey | null }> = {
  '筋力': { base: null },
  '敏捷力': { base: null },
  '知力': { base: null },
  '生命力': { base: null },
  '武術': { base: '筋力' },
  '怪力': { base: '筋力' },
  '剣術': { base: '敏捷力' },
  '運動': { base: '敏捷力' },
  '青の魔法': { base: '知力' },
  '赤の魔法': { base: '知力' },
  '緑の魔法': { base: '知力' },
  '鍛錬': { base: '生命力' }
} as const

// パラメータ (能力値・技能値) の管理を司るクラス

}
```

### 2. 装備

装備には、武器、盾、鎧がありますが、この中で定義が最も複雑になるのは武器になります。

#### 攻撃型

RPG.LOGIC の武器には、「叩」「切」「刺」の3タイプの「攻撃型」と呼ばれる属性があります。  
「叩」は相手の防具による影響を受けにくく、「刺」は影響を受けやすい特性を定義します。  
これは堅い鎧に対して、レイピアのような刺突攻撃は貫通しにくい、という物理法則を再現しています。

#### 両手武器

RPG.LOGIC の防御手段は、武器による「受け」、盾による「止め」、身体を左右に振って回避する「よけ」の3通りの方法がありますが、両手武器では「止め」を行えません。  
両手武器の方が性能値が大きい上、「受け」も有利に行えます。ただし、魔法による攻撃の多くは射撃であるため、「受け」では防ぐことができず、「止め」か「よけ」でのみ防ぐことができます。  
ゲーム・デザインとしてここで、【片手武器の戦士】 < 【両手武器の戦士】 < 【魔術師】 という、ジャンケンのような戦術的な相性関係が生じます。

#### 準備

棍棒や戦斧のような重量のある武器は、攻撃や「受け」での防御の都度、手元に武器を引き戻す「準備」という行為が必要になります。この間、武器は攻撃にも「受け」にも使えません。  
棍棒や戦斧は盾を別途使えますが、鉾槍は両手武器のため、一度攻撃を繰り出すと、その後の防御に懸念が残ります。その分、性能値は他の武器よりも高めに設定されています。

#### 必要筋力

武器・盾・鎧に共通して、その装備を扱うために必要な筋力を示します。  
ST(筋力)がその値に満たない場合は、その装備を扱えません。

##### 武器表

| 武器  | 性能値 | 攻撃型 | 用法  | 準備  | 必要ST | 金額  |
| --- | --- | --- | --- | --- | ---- | --- |
| 短剣  | 2   | 切   | 片手  | 不要  | -    | 10  |
| 小剣  | 2   | 刺   | 片手  | 不要  | -    | 20  |
| 長剣  | 3   | 切   | 片手  | 不要  | 11   | 40  |
| 大剣  | 4   | 切   | 両手  | 不要  | 13   | 80  |
| 棍棒  | 5   | 叩   | 片手  | 必要  | -    | 10  |
| 戦棍  | 6   | 叩   | 片手  | 必要  | 11   | 20  |
| 戦斧  | 5   | 切   | 片手  | 必要  | 13   | 40  |
| 長杖  | 4   | 叩   | 両手  | 不要  | -    | 10  |
| 長槍  | 3   | 刺   | 両手  | 不要  | 11   | 20  |
| 鉾槍  | 7   | 切   | 両手  | 必要  | 13   | 40  |

装備は、下記のようにコードで定義します。

```TypeScript

// 武器のキー
const WEAPON_KEYS = [
  '短剣', '小剣', '長剣', ...
] as const

type WeaponKey = typeof WEAPON_KEYS[number]

// 武器の定義

  dmgBase: number // 性能値

}

  '短剣': { dmgBase: 2, dmgType: 1, needsTwoHanded: false, needsReady: false, gold: 10 },
  '小剣': { dmgBase: 2, dmgType: 2, needsTwoHanded: false, needsReady: false, gold: 20 },
  '長剣': { dmgBase: 3, dmgType: 1, needsTwoHanded: false, needsReady: false, requiredST: 11, gold: 40 },
  ...
```

## 戦闘の実装

テーブルトークRPGでは、ダイス (サイコロ) を使って攻撃時の命中、回避、ダメージなどを判定します。  
複数のダイスを振った出目の合計と、その修正値を合わせて、例えば `2d+1` と表記すると、`2個`のダイスを振った出目の合計に、`1` を足す、という意味になります。  
また、出目が大きい方が有利に働く上方判定と、小さい方が有利に働く下方判定があります。

### 1. 判定

攻撃の命中や回避などの判定は `3d` で下方判定します。  
例えば目標値 (判定の基準値) が `10` なら、`10` 以下なら成功、`11` 以上なら失敗です。

ダイス3つの出目の合計の期待値は `10.5` なので、これは確率論で言うと、目標値が `10` ならちょうど50%の確率で成功・失敗が分かれます。  
なお、目標値には、先のキャラクタ作成で決めた能力値・技能値を用いる場合が多いため、能力値や技能値は、`10` を基準に考えると、キャラクタを作成し易いというゲーム・デザインになっています。

基本となる判定は、下記のようにコードで定義します。

```TypeScript
// src/domains/Combat/roll.ts

// ダイスを振った出目と修正値の合計を返す
// (3d: 六面体ダイス3個 をデフォルトとする)
function getRoll(count: number = 3, mod: number = 0, sides: number = 6): number {
  return Array.from<number>({ length: count }).reduce(sum => {
    return sum + Math.ceil(Math.random() * sides)
  }, 0) + mod
}

// 目標値を定めて判定結果を返す
function judge(target: number) {
  const roll = getRoll()
  const success = roll <= target
  return { roll, success }
}

```

### 2. ダメージ判定

攻撃の命中や回避はその成否を問うだけですが、ダメージは与えた致傷の度合いを返す必要があります。  
そのため、ダメージの判定は上方判定を用います。

武器の性能値と本人の筋力から算出したダメージステップに則って、`1d+2` とか `2d-1` とかいう表記でダメージ (打撃力) を表します。  
攻撃側のダメージ (打撃力) から防御側のダメージ抵抗 (服や鎧による防護力) を引き、その後「攻撃型」によって、実際にHp (耐久値) を削り取るダメージ倍率演算を加えます。

- 「叩」ならダメージはそのまま。
- 「切」ならダメージは1.5倍。
- 「刺」ならダメージは2倍

になります。

ダメージ判定の実装は煩雑なので、戦闘ロジックの実装を着手する頃に、再度コードを示します。  
ここでは、「あ、そういうルールなんだ」と理解して頂いて、実装を楽しみにしていてください。

### 制作フェーズと解説フェーズ

解説は大きく、以下の4つのフェーズに分けて行い、`1章 : 1ドメイン` に対応して執筆していく予定です。  
一方、制作フェーズは、キャラクタ作成までは解説フェーズと同様ですが、戦闘の実装から先はドメインごとの実装ではなく、各種コマンドごとに各々ドメインの実装を少しずつ進めてきました。  
当初は本著を元に少しずつゲームが出来上がる様子を体現してもらうような内容を理想としていましたが、100コミットを超える制作内容を書籍化するのは大変な労力を要するため、ドメインごとの解説に切り替えました。  
そのため、制作フェーズと解説フェーズで乖離が生じ、デモとソースコードは必ずしも章ごとに対応しておりませんので、その点はご容赦ください。  
実際にご自身の手でコードを書いていきたいという方は、GitHubリポジトリの方をご参考ください。コミットを整理しておきましたので、どのような順番で実装を着手したら良いか、分かり易くなっているはずです。
